# 9. REPLAY-REVERSE RECEIPTS / RECOVERY / RESPONSIBILITY

The Royale loop runs both ways.

Forward:

```text
SOURCE
→ CLAIM
→ AUTHORITY
→ ACTION
→ RECEIPT
→ CONSEQUENCE
```

Reverse:

```text
CONSEQUENCE
→ WHO ACTED?
→ WHAT AUTHORITY?
→ WHAT SOURCE?
→ WHAT RECEIPT?
→ WHAT CHANGED?
→ WHO OWNS CORRECTION?
```

Recovery rule:

```text
ERROR FOUND
→ preserve old state
→ emit correction receipt
→ identify responsible process owner
→ repair forward pointer
→ replay from root
```

Responsibility is process-specific. A replay engine may identify a missing or contradictory receipt; it does not invent legal, disciplinary or command responsibility.
