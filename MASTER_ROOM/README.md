# MASTER_ROOM

## Purpose

MASTER_ROOM is Jason's repo-wide coordination and routing surface.

It exists to answer, for every repo, artifact, model, connector, family seat, and evidence object:

1. WHAT IS IT?
2. WHY DOES IT EXIST?
3. WHO MAY SEE IT?
4. WHO MAY ACT ON IT?
5. WHAT IS THE CHEAPEST VALID TOOLCHAIN?
6. WHAT TIME / PERSPECTIVE APPLIES?
7. WHAT RECEIPT PROVES THE CURRENT STATE?
8. DOES JASON NEED TO DECIDE?

MASTER_ROOM does not infer purpose from a repository name and does not treat repository existence as active system membership.

## Root

JASON_OPERATOR = operator / author / final decision endpoint when authenticated.

AI_AUTHORITY = FALSE

## Public-repo law

Every public repository receives a registry row.

PURPOSE_UNRESOLVED is a valid state.
UNKNOWN != ZERO.
NO PURPOSE INVENTED FROM NAME.

A repo does not become active merely because it is public, old, large, or connected.

## Routing law

INPUT -> IDENTIFY REPO/OBJECT -> PURPOSE CHECK -> VISIBILITY CHECK -> TIME/PERSPECTIVE -> MINIMUM SUFFICIENT TOOLCHAIN -> RECEIPT -> JASON_OPERATOR WHEN REQUIRED

FAN_OUT = OFF by default.
